Agents and developers

Every scoring operation can be performed locally without submitting participant responses to a server.

Discovery

data/capabilities.v1.json — versioned operation and endpoint manifest

llms.txt and llms-full.txt — concise and expanded agent guidance

data/qcae.v1.json — canonical instrument, variants, items, scoring, and translation metadata

data/references.v1.json — papers, source records, active mappings, and integration candidates

Browser or JavaScript scoring

import { loadInstrument, scoreResponseDocument } from
  "https://jnton.github.io/Questionnaire-of-Cognitive-and-Affective-Empathy-QCAE-online-questionnaire/src/qcae-api.js";

const instrument = await loadInstrument();
const result = scoreResponseDocument(instrument, {
  locale: "en",
  responses: { "1": 2, "2": 3 /* ... all required items ... */ }
});

The module also exports variant listing, range calculation access, normalization, and validation helpers. It performs no telemetry or persistence.

Command line

node bin/qcae-score.mjs --list-variants
node bin/qcae-score.mjs examples/responses.en.synthetic.json
cat responses.json | node bin/qcae-score.mjs --locale tr -

Browser automation

The human questionnaire uses semantic HTML, stable IDs, labels, fieldsets, and data-qcae-* attributes. Select a locale with ?lang=en, ?lang=fr, ?lang=pt-PT, ?lang=de, ?lang=sr-Latn, or ?lang=tr. A read-only window.QCAE_APP object exposes version, locale, progress, current variant metadata, capability URL, and completed result export.

Compatibility boundary

There is no universal protocol implemented by every AI agent. This project supplies open web files, JSON, JSON Schema, ES modules, a CLI, semantic HTML, and explicit capability metadata so agents can integrate without scraping undocumented internals. Technical accessibility does not override content licences, consent requirements, or data-protection obligations.
